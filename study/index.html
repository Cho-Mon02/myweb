Map 컬렉션 인터페이스

한 줄 요약: Map은 키(Key)와 값(Value)의 쌍(Entry)으로 데이터를 관리하는 자료구조입니다. List나 Set과 달리 Collection 인터페이스를 상속하지 않는 독립적인 계층 구조를 갖습니다.

자세한 설명: 핵심 특징

  1. 키(Key)의 유일성: 키는 중복을 허용하지 않습니다. 동일한 키로 다시 저장(put)하면 기존 값이 새로운 값으로 덮어씌워집니다.
  2. 값(Value)의 중복 허용: 값은 중복될 수 있습니다. 서로 다른 키가 동일한 값을 가질 수 있습니다.
  3. 순서 보장 여부: 구현 클래스에 따라 다릅니다.

주요 구현 클래스

  • HashMap: 해시 테이블 기반. 순서를 보장하지 않으며, 삽입·삭제·검색의 평균 시간 복잡도가 O(1)로 가장 빠릅니다.
  • LinkedHashMap: 해시 테이블과 연결 리스트를 결합하여 데이터의 삽입 순서(또는 접근 순서)를 유지합니다.
  • TreeMap: 레드-블랙 트리(이진 탐색 트리) 기반. 키를 기준으로 오름차순 정렬하여 보관하며 탐색 시간 복잡도는 O(log N)입니다.

주요 메서드

  • put(K key, V value) : 키와 값을 추가하거나 기존 값을 수정합니다.
  • get(Object key) : 전달된 키에 해당하는 값을 반환하며, 키가 없으면 null을 반환합니다.
  • getOrDefault(Object key, V defaultValue) : 키가 존재하면 해당 값을, 없으면 지정한 기본값을 반환합니다.
  • containsKey(Object key) : 해당 키의 존재 여부를 boolean으로 확인합니다.
  • remove(Object key) : 키에 해당하는 엔트리를 삭제합니다.
  • keySet() : 모든 키를 Set 형태로 반환합니다.
  • entrySet() : 모든 키-값 쌍(Map.Entry)을 Set 형태로 반환합니다 (순회 시 가장 효율적).

     표준 구현 코드 예시
    Map scoreMap = new HashMap<>();

        // 추가 및 수정
        scoreMap.put("Alice", 95);
        scoreMap.put("Bob", 80);
        scoreMap.put("Alice", 100); // "Alice"의 값이 100으로 덮어씌워짐

        // 조회
        int aliceScore = scoreMap.get("Alice"); // 100
        int defaultScore = scoreMap.getOrDefault("Charlie", 0); // 0 (키가 없으면 기본값 반환)

        // 순회 (가장 권장되는 방식: entrySet)
        for (Map.Entry entry : scoreMap.entrySet()) {
        System.out.println(entry.getKey() + ": " + entry.getValue());
    }
  • 기억할 점 1 : 키(Key)는 중복 불가·값(Value)은 중복 가능: 이미 존재하는 키로 다시 저장(put)하면 기존 값이 새로운 값으로 덮어씌워집니다.
  • 기억할 점 2 : 커스텀 객체를 키로 쓸 땐 equals()와 hashCode() 필수 재정의: 두 메서드를 함께 구현하지 않으면 같은 데이터라도 해시 버킷 위치가 어긋나 값을 조회(get)할 수 없습니다.

개념 확인 문제

  1. 다음 중 Java의 Map 컬렉션에 대한 설명으로 올바르지 않은 것은?

    1. 키(Key)와 값(Value)의 쌍(Entry) 형태로 데이터를 관리한다.
    2. 키(Key)는 중복 저장을 허용하지 않지만, 값(Value)은 중복 저장이 가능하다.
    3. java.util.Collection 인터페이스를 직접 상속받아 구현된 인터페이스이다.
    4. 이미 존재하는 키로 새로운 값을 put()하면 기존 값은 새로운 값으로 갱신된다.
    정답 및 해설 보기

    정답: C

    해설: List와 Set은 Collection 인터페이스를 상속하지만, Map은 단일 원소가 아닌 키-값 쌍을 다루기 때문에 독립적인 구조를 가지며 Collection 인터페이스를 상속하지 않습니다.

  2. 다음 코드에서 map.get(key2)의 출력 결과가 null이 되는 원인으로 가장 정확한 것은?

    class User {
    private int id;
    public User(int id) { this.id = id; }

    @Override
    public boolean equals(Object o) {
        if (this == o) return true;
        if (!(o instanceof User)) return false;
        return this.id == ((User) o).id;
    }
}

// 실행 코드
Map map = new HashMap<>();
User key1 = new User(100);
User key2 = new User(100);

map.put(key1, "Admin");
System.out.println(map.get(key2)); // 출력: null
    1. User 클래스의 id 필드가 final로 선언되지 않았기 때문이다.
    2. equals() 메서드에서 instanceof 대신 getClass()를 써야 정상 동작하기 때문이다.
    3. hashCode()를 오버라이딩하지 않아 두 객체가 서로 다른 해시 버킷(Bucket)을 참조하기 때문이다.
    4. HashMap은 키로 커스텀 클래스를 지원하지 않고 기본 래퍼 타입(Integer, String 등)만 허용하기 때문이다.
    정답 및 해설 보기

    정답: C

    해설: HashMap은 데이터를 조회할 때 먼저 키의 hashCode()를 호출해 버킷의 위치를 찾습니다. equals()만 재정의하고 hashCode()를 재정의하지 않으면 최상위 Object의 기본 해시코드(메모리 주소 기반)가 사용되어, 필드 값이 같아도 서로 다른 버킷을 탐색하므로 equals() 비교 단계까지 가지 못하고 null을 반환합니다.
